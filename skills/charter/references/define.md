# Define

Create a draft charter from a new objective or an existing discussion. Do not implement the capability, produce its implementation plan, or create tasks.

First decide whether the objective warrants a charter. Recommend an ordinary task instead when it is one independently verifiable unit, needs no shared project commitment, or would make every charter section ceremonial. Explain the concrete reason and stop unless the operator explicitly keeps the charter.

For a warranted charter:

1. Use the discussion and repository evidence already available.
2. Establish the objective, why it earns commitment now, baseline, scope dispositions, decisions, observable definition of done, and non-goals.
3. Resolve repository-answerable questions before asking the operator. If material terrain remains unclear, recommend explicit `recon`; do not manufacture a baseline.
4. Ask only for choices or unavailable facts that materially affect commitment or acceptance.
5. Show the complete proposed record with `status: draft`. Do not write incrementally.
6. After operator acceptance, validate the id, confirm no collision, create the file once, and stop unless the same message asks for another action.

Keep downstream task candidates in `## Tasks` only as proposed references when they already exist. A prospective task is not a reference; leave task creation to the task workflow.
